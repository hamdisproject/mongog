# ADR-0007: Monaco type loading — build-time d.ts manifest (ambient-module wrapping)

- Status: Accepted (validated by S6: cold 34 ms, warm 8 ms; 87 files / 2.08 MB)
- Context: Autocomplete for the INSTALLED driver, no hand-maintained lists, no CDN.
- Options: ship & read node_modules at runtime; CDN (rejected); build-time extraction.
- Decision: **Build-time extraction** (`scripts/extract-mongo-types.mjs`): crawl `mongodb/mongodb.d.ts` (api-extractor rollup) + `bson` + referenced `@types/node` builtins; wrap entry files as ambient modules (`declare module "mongodb" { … }` — script file, NO trailing `export {}` or it becomes a failing augmentation); emit `src/renderer/generated/mongo-types.manifest.json` (virtual paths `file:///node_modules/...` + synthetic globals `mongodb/bson/client/db/use/print/printjson`). Cache key = mongodb+bson(+monaco) versions; regenerated by prestart/prepackage hooks.
- Consequences: completions automatically track the installed driver version; Monaco 0.56 API is the top-level `typescript` namespace (NOT `monaco.languages.typescript`); worker imports need the exports-map form (`monaco-editor/editor/editor.worker.js?worker`).
- Risks: multi-MB extra libs slowing the TS worker (not observed: 34 ms cold). Revisit: TS worker init >2 s → trim via api-extractor or lazy bson sub-paths.
